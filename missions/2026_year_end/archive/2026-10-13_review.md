# 제어 개념과 시뮬레이션 검토 (2026-10-13)

> 보관용 기록입니다. `aeroprop-v2`로 바꾸기 전의 코드와 [2026-10-08 결과](2026-10-08_report.md)를
> 검토했습니다. 여기서 찾은 문제는 대부분 그 뒤에 고쳤고, 2절의 표에 항목마다 현재 상태를 적었습니다.
> 지금의 모델은 [3. 시뮬레이션](../../../docs/03_simulation.md), 실행 결과는 [보고서](../report.md)에
> 있습니다.

검토한 것은 기체·PX4 설정, Gazebo 모델 생성기, 임무 프로파일, 판정 코드, ROS 2 노드, 기존 결과입니다.
논문과 PX4·Gazebo 공식 소스도 대조했습니다. 당시 저장소에는 PX4·Gazebo 빌드와 원본 ULog가 없어서 기존
비행을 다시 돌려 보지는 못했고, 단위 시험(당시 20개), 독립 계산, 합성 데이터 검사만 실행했습니다.

## 결론

- 저속에서 푸셔로 보조하는 멀티콥터라는 개념은 물리적으로 타당하고 연구 근거도 있습니다.
- stock PX4 v1.17.0은 MC 상태에서 푸셔 보조를 지원합니다(`Standard::update_mc_state()`,
  `VtolType::pusher_assist()`).
- 당시 시뮬레이션은 구현 가능성과 민감도를 보는 데는 유용했지만, 10 m/s 순항, 8 m/s 바람, 제동·착륙
  성능, 비행 준비 완료를 보여 주지는 못했습니다.
- 다음 노력은 게인 조정이나 무작위 비행 횟수를 늘리는 것보다 판정 보완, 실측 입력, 측풍·역류·제동 공력,
  로터 여유 검증에 써야 한다고 판단했습니다.

## 1. 기체 수치로 본 가능성과 한계

YAML 값으로 계산한 것이고 실측이 아닙니다. 계산 코드는 [`checks.py`](../evaluation/checks.py)입니다.

- 무게 68.65 N, 리프트 최대 추력 합 130.4 N, 추력비 1.90. 정적 호버 여유는 있습니다.
- 날개 면적 0.425 m², 종횡비 6.8, 유한 날개 양력 기울기 4.51/rad.
- 붙임각 0°, 10 m/s 수평 비행에서 날개 양력은 8.06 N으로 무게의 11.7%입니다. 로터가 무게 대부분을
  드는 멀티콥터라는 가정과 맞습니다.
- 25 N 푸셔로 낼 수 있는 가속은 항력이 없어도 3.57 m/s²입니다. 푸셔 보조 명령 상한 0.9를 적용하면
  22.5 N이고, 여기서 항력·전압 강하·유입 손실을 빼야 실제 여유가 됩니다.
- 10 m/s에서 1 m/s²로 멈추는 데 이상적으로 50 m가 필요합니다. 가속 50 m + 순항 150 m + 감속 50 m로 임무
  전체가 약 250 m이므로 시험장 경계에 맞춘 설계가 필요합니다.

### 날개 부담은 pitch에 민감하다

`L/(mg) = ρ V² S CL(α) / (2mg)`이므로 속도뿐 아니라 받음각이 중요합니다. 수평 기류와 고도 유지를 가정한
계산입니다. 6.4°는 이전 결과에서 나온 제동 자세를 예로 쓴 것입니다.

| 붙임각 | 대기속도 | pitch 0° | pitch +6.4° |
|---|---:|---:|---:|
| 0° | 10 m/s | 11.7% | 30.5% |
| 0° | 18 m/s | 38.0% | 98.9% |
| 4° | 10 m/s | 23.5% | 42.3% |
| 4° | 13 m/s | 39.7% | 71.4% |

수평 비행에서 40%가 되는 속도(붙임각 0°에서 18.46 m/s, 4°에서 13.05 m/s)를 그대로 운용 상한으로 쓰면
제동이나 돌풍에서 로터가 크게 언로드될 수 있습니다. 강한 정풍에서는 대지속도를 0으로 낮춰도 대기속도가
높으므로, 속도 제한만으로 안 되는 바람에 대한 중단·귀환·착륙 전략도 필요합니다.

### yaw 게인으로는 물리적 한계를 늘릴 수 없다

모터당 Tmax = 32.6 N, 반토크 계수 0.030 m일 때 다른 축 요구가 없다면 `|Mz| ≤ kQ × min(T, 4Tmax − T)`입니다.

| 날개 부담 | 이상적인 yaw 토크 상한 |
|---|---:|
| 0% | 1.85 N·m |
| 40% | 1.24 N·m |
| 59% | 0.84 N·m |
| 80% | 0.41 N·m |

날개 부담이 클수록 여유가 줄어든다는 방향은 맞지만, 40%면 충분하다고 결론 내릴 근거는 없습니다. 당시
문서의 "푸셔 오프셋을 몰라도 된다"는 표현도, 정상 토크가 허용 범위 안이고 응답이 느릴 때 적분기가 보상할
수 있다는 뜻으로 고쳐야 했습니다.

## 2. 찾은 문제와 현재 상태

| 영역 | 당시 문제 | 현재 상태 |
|---|---|---|
| 공력 | Gazebo LiftDrag가 `forward · 상대속도 ≤ 0`이면 힘을 0으로 계산해 배풍·순수 측풍에서 면 공력이 사라짐 | 고침. 자체 플러그인이 실속 후 평판 근사로 넘어가며 역류에서도 힘이 남음 |
| 공력 | 항력을 `CD0/α0 × α`로 맞춰 피치 −4°에서 CL과 CD가 모두 0 | 고침. `CD = CD0 + CL²/(π e AR)` |
| 공력 | 양력 작용점을 옮겨 pitching moment를 흉내 냄 | 고침. 독립된 `wing_cm0` |
| 공력 | 모든 모터에 숨은 `rotorDragCoefficient`가 순항 로터 항력의 대부분(약 4.35 N, 날개 항력 2.05 N)을 차지하는데 스윕되지 않음 | 고침. Gazebo 쪽은 0으로 끄고 YAML의 `lift_drag_at_full_rpm`으로 옮겨 스윕 |
| 추진 | 추력이 회전수 제곱뿐이고 유입·전압 영향 없음 | 일부 고침. 축방향 유입 손실과 스크립트 전압 감소 추가. 전류·발열·SOC는 없음 |
| 판정 | 필수 지표가 모두 NaN이어도 통과 | 고침. 없거나 NaN이면 실패 |
| 판정 | 속도 0, 경로 오차 100 m, 기수 오차 180°, 푸셔 포화 100%, 착륙 오차 100 m도 통과 | 고침. 해당 지표를 기준에 추가 |
| 판정 | tilt를 호버–호버 구간만 봐서 상승·착륙 중 75° roll을 놓침 | 고침. 상승부터 착륙까지 |
| 판정 | 수평으로 전혀 움직이지 않아도 프로파일이 완료됨 | 고침. 가속 단계가 실제 속도 도달을 요구 |
| 판정 | runner의 60° 중단 검사가 상승·착륙을 제외 | 고침. 모든 단계에 적용 |
| 판정 | 착륙 완료를 disarm만으로 판단 | 고침. land detector의 landed 확인 필요 |
| 판정 | 토크 미달을 시간 비율로만 봐서 연속 미달을 숨김. 최소 추력 쪽 포화를 안 봄 | 고침. 최장 연속 시간과 하한 도달 비율 추가 |
| 판정 | 상승·하강의 수직 추종 오차 지표가 없음 | 열림 |
| ROS 2 | `setpoint_mux`의 HOLD가 매번 현재 위치를 목표로 보내 5 m 밀리면 목표도 5 m 이동 | 고침. 들어간 순간의 위치와 기수를 고정 |
| ROS 2 | `source.py`가 메시지 유효성과 수신 경과시간을 확인하지 않음 | 고침. 1초 넘게 끊기면 `FAILED`로 고정 |
| ROS 2 | mission_manager의 status timeout이 경고만 함 | 고침. `FAILSAFE`로 전환 |
| PX4 설정 | `VT_LND_PITCH_MIN` 기본값 −5°가 Land에서 0° 설정을 덮어쓰고, `VT_FWD_THRUST_EN=4`가 착륙 중 푸셔를 배제하지 않음 | 고침. `VT_FWD_THRUST_EN=5`, `VT_LND_PITCH_MIN=0` |
| PX4 설정 | 4004에서 상속한 `CA_ROTORn_KM` 크기(0.05)와 모델의 물리 계수(0.03)가 다름 | 바뀜. KM은 모델 값을 쓰고 공통 CT 6.5로 yaw 행 제거를 피함 |
| 임무 | 지정한 착륙 좌표로 유도하지 않음 | 열림 |
| 운용 | SITL은 RC·데이터 링크 failsafe를 꺼서 실제 상실·저전압·지오펜스·귀환을 검증하지 않음. 푸셔 고장 시 자동 대체 없음 | 열림 |

당시 판정 결함을 재현한 합성 검사 결과는 [`results.json`](../evaluation/results.json), 고친 뒤 같은 검사를
돌린 결과는 [`revised_checks.json`](../evaluation/revised_checks.json)에 있습니다.

## 3. 결과를 해석할 때 주의할 점

- **38/40은 성공 확률이 아니다.** 25차원에서 40회 균등 표본은 탐색입니다. 선택한 분포의 독립 표본이라고
  가정해도 95% Wilson 구간은 약 83.5–98.6%이고, 실제 기체와 바람의 분포가 아니므로 현실의 성공 확률이
  아닙니다.
- **OAT 48건은 기준 기체를 포함한다.** 보고서의 기준 기체 행과 48/48을 더해 49건으로 세면 안 됩니다.
- **wind 스터디는 yaw 게인 두 가지를 비교한 것이다.** `heading_into_wind`를 바꾼 시험이 아닙니다. 그걸
  시험하려면 참 바람 대신 실제 풍속 추정의 오차와 지연을 넣어야 합니다.
- **호버 명령 0.52는 검증이 아니다.** eCalc 추력비를 모델에 넣었으니 1/1.9가 나오는 것은 구현이
  일관된다는 확인입니다. 모델 검증에는 독립된 실측과의 비교가 필요합니다
  ([NASA 모델·시뮬레이션 FAQ](https://public.ksc.nasa.gov/mns/faq/)).
- **OAT와 random만으로는 위험한 조합을 놓친다.** 최대 질량 + 최소 추력 + 최대 CG 편차 + 강한 바람 + 높은
  붙임각 + 제동 + 전압 강하를 일부러 겹쳐야 합니다. 지금은 corner 스터디가 이런 조합을 다룹니다.
- **좌우 바람은 대칭이 아니다.** 오프셋과 모터 불일치가 있으면 대칭이 깨지므로 양쪽을 시험합니다.

## 4. 당시 제안한 우선순위

| 순서 | 작업 | 필요한 증거 |
|---|---|---|
| 1 | 원자료 보존과 판정 보완 | ULog, 단계 시간, 전체 파라미터, 버전·커밋; 단계별 자세·속도·경로·착륙·포화·토크 판정 |
| 2 | 기체 실측 | 전비중량, CG, 관성, 장착각, 추력선; 전압별 추력·토크·RPM·전류, 온도, 모터 응답 |
| 3 | 공력·추진 모델 개선 | 역류·측풍에서 힘이 사라지지 않는지; CL/CD/Cm과 동적 추력, 간섭과 로터 항력 민감도 |
| 4 | 운용 범위 산출 | 속도·받음각·풍향별 trim과 축 결합 토크 여유; 제동, 수직 돌풍, 전압 강하, 지연에서의 회복 |
| 5 | ROS 2 경로와 복구 시험 | 고정 HOLD, 상태 신선도, 푸셔 고장·토픽 단절·RC·offboard·저전압; 착륙 좌표와 거리 기준 제동 |
| 6 | 단계적 실측 비교 | 지상 추진 시험 → 구속 호버 → 저속 푸셔 → 점진적 속도 확대 |

관리합니다.

## 5. 검사 다시 돌리기

프로젝트 의존성과 pytest가 있는 Python으로 repo 최상위에서 실행합니다.

```bash
python3 -m pytest -q
python3 missions/2026_year_end/evaluation/checks.py
```

`checks.py`는 비행 동역학을 돌리지 않습니다. 정적 계산, 합성 로그, 프로파일 입력, HOLD 메서드 단독 실행으로
위의 수치와 판정 동작을 다시 만듭니다.
