# 2. 제어 개념과 PX4 설정

이 기체는 **리프트 모터 네 개로 자세를 잡고, 푸셔 한 개로 앞으로 가는 quadplane**입니다.
조종면 없이 비행하는 구성은 연구와 저속 실내 비행 사례가 있습니다. 다만 우리 기체의
고속·측풍 비행이 검증된 것은 아닙니다. 현재 출발점은 PX4 v1.17.0의 멀티콥터 제어와
푸셔 보조 기능입니다. custom PX4는 제어 여유를 확인하면서 단계적으로 검토합니다.

2026-10-13에 시뮬레이션 모델과 판정 기준을 변경했습니다. 기존 보고서의 통과율과 튜닝값은
이전 모델의 기록입니다. 새 모델은 Docker에서 nominal 전체 임무·착륙이 통과했으며,
실행 수치와 한계는 [새 보고서](../missions/2026_year_end/revised_simulation_report.md)에 있습니다.

## 1. 먼저 이해할 것

| 원하는 움직임 | 만드는 방법 | 기억할 한계 |
|---|---|---|
| 상승·하강 | 리프트 모터 네 개의 추력 합 | 날개 양력도 수직 힘에 더해짐 |
| Roll·pitch | 좌우·앞뒤 모터 추력 차 | 모든 모터에 올리고 내릴 여유가 필요 |
| Yaw | CW/CCW 모터의 반토크 차 | 이 구성에서 가장 약한 축 |
| 전진 | 푸셔 | 기수 방향으로만, 양의 추력만 가능 |
| 제동 | 푸셔를 줄이고 기수를 들어 리프트 추력을 뒤로 기울임 | 받음각과 날개 양력이 증가함 |
| 측풍 보상 | 기체를 옆으로 기울이거나 기수 방향 조정 | yaw·수직 추력 여유를 함께 사용 |

날개 양력은 속도와 자세에 따라 바뀝니다. 날개가 무게를 많이 들수록 리프트 모터의 평균
추력은 줄고, 자세 제어에 쓸 수 있는 추력 차도 작아질 수 있습니다. 특히 제동 중에는
기수가 올라가므로, 수평 순항에서 여유가 있어도 제동에서 여유를 잃을 수 있습니다.

간단한 수평 비행 근사에서는 `리프트 추력 합 ≈ 무게 − 날개 양력`입니다. 한 모터의 최대
추력을 Tmax, 추력 합을 T라고 하면, 다른 축의 요구가 없는 이상적인 yaw 상한은
`|Mz| ≤ kQ × min(T, 4Tmax − T)`입니다. 실제 상한은 CG, pitch/roll 요구, 지연,
장착 간섭 때문에 더 작습니다. yaw 게인을 올려도 이 물리적 상한은 늘어나지 않습니다.

## 2. 현재 비행 순서

모든 단계에서 **VTOL 상태는 MC**로 둡니다. 여기서 가속·감속은 속도 변화이며 PX4의
고정익 천이 명령을 뜻하지 않습니다.

| 단계 | Companion이 보내는 것 | 완료 조건 |
|---|---|---|
| 상승 | 이륙 지점 x/y, 목표 고도 | 고도에 도달하고 수직 속도가 작음 |
| 호버 | 같은 위치 | 설정한 호버 시간 |
| 가속 | 고도 유지, 전진 속도를 ramp로 증가 | ramp 완료와 실제 전진 속도 도달 모두 필요 |
| 순항 | 고도·전진 속도 유지 | 설정한 시간; 사후에 속도·경로 오차 판정 |
| 감속 | 속도 ramp를 0까지 감소 | 수평 속도 0.5 m/s 미만 |
| 두 번째 호버 | 감속이 끝난 위치를 고정 | 설정한 호버 시간 |
| 하강 | 고정 x/y, 아래로 1.5 m/s 명령 | 지면 기준 4 m 아래 |
| 착륙 | PX4 MC Land 모드 요청 | 프로파일은 disarm, 최종 판정은 landed 로그도 필요 |

기본 임무는 고도 20 m, 순항 10 m/s, 속도 ramp 1 m/s², 순항 15초입니다.
값은 [`mission.yaml`](../missions/2026_year_end/mission.yaml), 순서는
[`profile.py`](../psi_vtol/profile.py)에 있습니다. **지정 좌표에 도착하는 경로 계획은 아직 없습니다.**
현재 착륙 목표는 감속 후 멈춘 지점입니다. 착륙 오차 기준도 이 지점에 대한 오차입니다.

## 3. PX4가 하는 일과 Companion이 하는 일

Companion의 ROS 2 노드는 위치·속도·기수 방향 setpoint만 만듭니다. PX4가 상태 추정,
위치/속도 제어, 자세/각속도 제어, 모터 할당을 담당합니다. `setpoint_mux`가 20 Hz로
선택한 단계의 명령만 전달합니다.

PX4의 `pusher_assist()`는 전진하려고 기수를 숙이는 요구를 푸셔 명령으로 바꿉니다.
`VT_PITCH_MIN=0`일 때 이 기능이 활성화된 구간에서는 전진을 위한 nose-down 대신
푸셔를 사용합니다. **전체 비행에서 pitch가 항상 0°라는 뜻은 아닙니다.** 제동에는 pitch-up이
필요하고, 보조 기능이 꺼지는 저고도·Land에서는 일반 MC 방식으로 기울여 이동합니다.

v1.17.0의 푸셔 보조 명령은 0.9에서 제한됩니다. 포화돼도 부족한 전진력을 자동으로
nose-down에 다시 배분하지 않습니다. 따라서 약한 푸셔·정풍에서 속도 미달이 생길 수 있습니다.
이 동작은 [PX4 v1.17.0 소스](https://github.com/PX4/PX4-Autopilot/blob/v1.17.0/src/modules/vtol_att_control/vtol_type.cpp)의
`pusher_assist()`를 기준으로 설명했습니다.

## 4. PX4 설정을 준비하는 순서

### 4.1 버전과 기체 형식

1. 기준 펌웨어는 **PX4 v1.17.0**, ROS 메시지는 **px4_msgs v1.17.0**으로 맞춥니다.
2. SITL은 airframe **4004 `gz_standard_vtol`** 위에 우리 설정을 적용합니다.
   4004는 Gazebo용입니다. Pixhawk에 사용할 하드웨어 airframe ID가 아닙니다.
3. 실제 보드는 standard VTOL을 바탕으로 기체 전용 airframe 설정을 준비합니다.
   `CA_AIRFRAME=2`, `VT_TYPE=2`, 로터 5개, 조종면 0개가 제어 구성의 출발점입니다.
4. QGroundControl에서 센서 방향·보정, 출력 프로토콜, RC, 전원 모듈, 위치 센서를 보드에 맞게
   설정합니다. 이 정보는 repo의 모델 수치에서 자동으로 결정되지 않습니다.

### 4.2 모터 순서와 좌표

PX4는 **x 앞, y 오른쪽, z 아래(FRD)**를 씁니다. 아래는 현재 가정한 CG 기준 치수입니다.
실제 CG를 측정한 뒤 다시 계산해야 합니다. 시뮬레이션의 CG 편차 스윕은 PX4에 알려 주지 않는
모델 오차로 남겨 둡니다.

| 모터 index / 출력 기능 | 위치 | PX4 x, y, z (m) | 추력축 AX, AY, AZ | KM |
|---|---|---|---|---|
| 0 / Motor 1 | 앞 오른쪽, CCW | +0.3325, +0.2525, −0.07 | 0, 0, −1 | +0.030 |
| 1 / Motor 2 | 뒤 왼쪽, CCW | −0.3325, −0.2525, −0.07 | 0, 0, −1 | +0.030 |
| 2 / Motor 3 | 앞 왼쪽, CW | +0.3325, −0.2525, −0.07 | 0, 0, −1 | −0.030 |
| 3 / Motor 4 | 뒤 오른쪽, CW | −0.3325, +0.2525, −0.07 | 0, 0, −1 | −0.030 |
| 4 / Motor 5 | 푸셔 | −0.40, 0, 0 | 1, 0, 0 | 0 (stock 할당 설정) |

회전 방향은 각 프로펠러의 양의 추력축 쪽에서 내려다보는 기준입니다. QGC의 모터 테스트로
실제 위치·회전 방향·추력 방향을 하나씩 대조합니다. 모터 index는 보드의 물리 커넥터 번호와
다릅니다. QGC Actuators에서 각 커넥터에 Motor 1–5 기능을 연결해야 합니다. 프로펠러를
제거한 상태에서 출력과 회전 방향을 먼저 확인합니다.

`CA_ROTORn_CT=6.5`는 다섯 모터에 동일하게 적용한 할당기의 상대 계수입니다. N 단위의
최대 추력이 아닙니다. PX4 v1.17은 효과 행렬의 한 행이 모두 절댓값 0.05 이하이면 그 축을
제거합니다. CT=1, |KM|=0.03에서는 **yaw 행이 지워지는 것을 실제 SITL에서 확인**했습니다.
공통 CT 배율을 6.5로 두면 yaw 계수는 0.195가 되어 이 수치 문턱을 넘습니다. 정규화된
할당에서의 공통 배율이며 물리 추력이나 반토크를 키운 변경이 아닙니다.
[행 제거 코드](https://github.com/PX4/PX4-Autopilot/blob/v1.17.0/src/modules/control_allocator/ControlAllocator.cpp)와
[정규화 코드](https://github.com/PX4/PX4-Autopilot/blob/v1.17.0/src/lib/control_allocation/control_allocation/ControlAllocationPseudoInverse.cpp)를 함께 확인합니다.
KM은 부호를 포함한
반토크/추력 비이며 지금 값도 측정값이 아닙니다. stock standard-VTOL 할당기는 수평 로터의
프로펠러 반토크를 비활성화합니다. 현재 후보 설정은 푸셔 PY/PZ도 0으로 두므로 푸셔의 실제
roll 반토크와 pitch/yaw 오프셋은 리프트 자세 루프가 외란으로 받아 보상합니다.
오프셋이 커지면 적분기·모터가 포화할 수 있으므로 "오프셋을 몰라도 된다"고 보아서는 안 됩니다.

### 4.3 설정값과 의미

설정 원본은 [`px4/params.yaml`](../px4/params.yaml)입니다.

| 설정 | 현재 값 | 의미와 확인할 점 |
|---|---|---|
| `CA_ROTOR_COUNT`, `CA_SV_CS_COUNT` | 5, 0 | 다섯 모터, 조종면 없음 |
| `VT_FWD_THRUST_EN` | **5** | `MPC_LAND_ALT1` 이상에서 보조, auto Land/descend에서는 끔 |
| `VT_PITCH_MIN` | 0° | 보조가 켜진 구간의 전진 pitch 처리 |
| `VT_LND_PITCH_MIN` | 0° | landing override를 명시; mode 5로 보조가 꺼지면 적용되지 않음 |
| `VT_FWD_THRUST_SC` | 2.75 | W/Tp,max에서 시작한 가정. 실제 추력·속도·날개 부담에 맞춰 재평가 |
| `CA_R4_SLEW` | 1.0 s | 푸셔 명령의 0→1 변화에 최소 1초 |
| `CA_ROTOR4_PY`, `_PZ` | 0, 0 | stock 기준선은 푸셔 오프셋을 할당에 반영하지 않음 |
| `THR_MDL_FAC` | 1.0 | 시뮬레이터의 정적 제곱 추력 모델. 실기는 벤치 곡선으로 결정 |
| `MC_YAWRATE_K` | 3.0 | 이전 SITL 튜닝값. 새 모델·실기에 검증된 값 아님 |
| `MPC_XY_VEL_MAX` | 16 m/s | setpoint가 잘리지 않게 하는 상한. 검증된 운용 속도 아님 |
| `WV_EN` | 0 | 기수 방향은 미션 노드가 지정 |
| `RTL_TYPE` | 0 | 직접 Return 기준선. 실제 failsafe 경로 별도 시험 |

mode 5의 고도 판단은 거리 센서 또는 home/local 고도에서 계산합니다. `MPC_LAND_ALT1`의
실효값도 확인해야 합니다. 경계 통과 시 보조의 켜짐/꺼짐이 바뀌며 현재 custom hysteresis는 없습니다.
정확한 enum은 [v1.17.0 헤더](https://github.com/PX4/PX4-Autopilot/blob/v1.17.0/src/modules/vtol_att_control/vtol_type.h)에 있습니다.

### 4.4 검토용 파라미터 파일 만들기

```bash
bash simulation/docker_run.sh python3 -m psi_vtol.px4_setup --output /workspace/psi_candidate.params
```

이 파일은 QGC 형식의 **검토용 후보**입니다. 기하와 `concept`, `per_vehicle`을 담고
`sim_only`는 제외합니다. 추력·CG·게인은 여전히 가정값입니다. 측정값으로 원본을 고치고
다시 생성한 뒤 QGC에서 비교·적용합니다. 출력 핀, 센서 보정, RC와 failsafe는 포함하지 않습니다.
SITL runner는 부팅 후 요청한 파라미터의 응답값을 비교하고 전체 실효값 덤프도 저장합니다.

실기에서 별도로 확인할 설정은 다음과 같습니다.

- Offboard loss: `COM_OF_LOSS_T`, `COM_OBL_RC_ACT`와 실제 RC 유무에 따른 동작.
- RC·데이터 링크·배터리·지오펜스·위치 추정 상실 시 행동. `sim_only`의 failsafe 해제값을 실기에 복사하지 않습니다.
- `MPC_LAND_ALT1/2`, `MPC_LAND_SPEED`, `COM_DISARM_LAND`와 지면 기준 고도.
- 대기속도 센서를 설치했다면 센서 수·방향·보정·유효성. 현재 stock 기준선과 미션 노드는
  대기속도로 운용 상한을 자동 제한하지 않습니다.

PX4는 Offboard 진입 전에 정상적인 명령 스트림을 요구하며 스트림이 끊기면 설정된 loss
동작을 수행합니다. ROS watchdog은 스트림을 멈출 수 있지만 PX4 failsafe 설정 자체를 대신하지 않습니다.
[PX4 Offboard 문서](https://docs.px4.io/v1.17/en/flight_modes/offboard)를 함께 확인합니다.

### 4.5 고정익 천이가 발생하지 않게 하기

현재 노드는 `VEHICLE_CMD_DO_VTOL_TRANSITION`을 보내지 않습니다. RC 천이 스위치를
매핑하지 않고 VTOL 이륙·천이·고정익 미션 항목도 업로드하지 않습니다. Return, geofence,
link loss와 수동 모드 변경을 SITL에서 각각 시험해 MC 유지와 리프트 모터 작동을 로그로 확인합니다.
단순히 `VT_FW_DIFTHR_EN`을 켜는 것은 이 설계용 통합 제어기를 만드는 방법이 아닙니다.

## 5. 시험을 진행하는 순서

1. 새 공력 플러그인 빌드와 단위 시험 → 무풍 nominal SITL.
2. 속도·wing lift·양쪽 모터 한계·토크 미달·착륙을 확인 → OAT와 양쪽 측풍 시험.
3. 약한 푸셔/정풍, 높은 날개 양력/제동, 저전압/장착 손실을 겹친 corner 시험.
4. 실제 ROS 2 노드로 반복하고 노드 종료·상태 토픽 중단·Offboard loss를 주입.
5. 실제 질량·CG·관성·추력 곡선을 반영한 뒤, 구속 호버와 저속 푸셔 시험부터 비교.

10 m/s와 날개 부담 40%는 현재 시험을 시작하기 위한 값입니다. 측정이나 새 SITL로
확정한 비행 허용 범위가 아닙니다. custom PX4의 선택 기준과 구현 순서는
[7. 연구와 custom PX4](07_research_and_custom_px4.md)에 정리했습니다.
